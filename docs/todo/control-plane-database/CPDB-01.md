# CPDB-01: inventaris dan kontrak pemisahan

CPDB-01 menghasilkan baseline read-only dan kontrak implementasi. Database tujuan tetap `core_control_plane`. Belum ada koneksi baru, migration, copy, perubahan hak akses, atau perubahan perilaku aplikasi dari unit ini.

Status unit adalah `in_review`. Inventaris dan keputusan CPDB-01a sampai CPDB-01i tersedia untuk review. Pengujian cutover, hak database negatif, delivery projection, revoke, dan pemulihan tetap pekerjaan berikutnya. Urutan program mengikuti [HANDOFF](HANDOFF.md).

## Cara membaca bukti

| Label              | Arti pada laporan ini                                                                                           |
| ------------------ | --------------------------------------------------------------------------------------------------------------- |
| `source-only`      | Terlihat pada blob source dengan SHA yang disebutkan. Belum membuktikan jalur itu dieksekusi runtime.           |
| `runtime-verified` | Metadata atau agregat diambil dari koneksi yang diperiksa. Bukan bukti semua workflow benar.                    |
| `target-design`    | Kontrak yang harus dipenuhi implementasi berikutnya. Belum tersedia sebagai schema, endpoint, atau enforcement. |
| `unknown`          | Belum mempunyai bukti. Tidak dihitung sebagai acceptance yang lulus.                                            |

Semua path source pada halaman ini relatif terhadap root repository. Nomor baris rinci ada pada `sites` dan `operations` di `inventory/source-references.json`, dengan SHA baseline yang sama. JSON di folder `inventory/` adalah berkas audit, bukan endpoint produk.

| Berkas                             | Isi dan cara memeriksanya                                                                                                                               |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `inventory/runtime-dev1.json`      | Config efektif yang sudah disaring, probe PDO, image digest/revision, katalog dua database, agregat aman, dan sampel latency.                           |
| `inventory/ownership-rules.json`   | Keputusan eksplisit move/retain/projection, partisi domain, dan pengecualian migration historis.                                                        |
| `inventory/manifest.json`          | Setiap objek runtime, keputusan tabel, model marker, calon writer source, serta ringkasan coverage.                                                     |
| `inventory/migrations.json`        | Migration Core/module, hash source, tabel yang disebut, dan keputusan target/history.                                                                   |
| `inventory/source-references.json` | Referensi tabel/model, join/subquery, whereHas, eager loading, transaksi, actor, dan koneksi. Kandidat lexical diberi kontrak pengganti X01 sampai X12. |
| `inventory/field-partitions.json`  | Keputusan per field untuk organisasi, company, party, dan alamat. Tidak memuat nilai field.                                                             |
| `inventory/contracts.json`         | Kontrak identity, authority, projection, policy/profile, acknowledgement, custody, dan pembayaran. Semua `target-design`.                               |
| `inventory/decisions.tsv`          | Jejak keputusan dan koreksi bukti.                                                                                                                      |

Jalankan dari root repository:

```bash
python -m unittest discover -s scripts -p test_cpdb_inventory.py -v
python scripts/cpdb-inventory.py --check
node scripts/check-healthcare-domain-neutrality.mjs
```

Generator membaca blob Git pada SHA di `ownership-rules.json`, bukan file kerja sesi lain. Hash seluruh input source dan snapshot runtime dicatat pada manifest. `--check` tidak menghubungi server. Untuk mengambil snapshot baru, baca lagi alias SSH `dev1` dan konfigurasi runtime yang sah, lalu jalankan:

```bash
python scripts/cpdb-runtime.py --output docs/todo/control-plane-database/inventory/runtime-dev1.json
python scripts/cpdb-inventory.py
```

Collector membaca config cached atau memakai loader konfigurasi Laravel tanpa boot provider. SQL hanya metadata/agregat dengan `default_transaction_read_only=on` dan statement timeout. Tidak menjalankan artisan, membuka UI, membuat file remote, menampilkan query sesi, atau menyimpan nilai credential. Koneksi MCP PostgreSQL mesin ini menunjuk host lokal, sehingga tidak dipakai untuk menyamar sebagai koneksi dev1.

## Ownership yang dikunci

`move` berarti authority masuk database pusat. `retain` berarti tetap pada database bisnis atau partisi historis yang disebut. `projection` berarti objek harus dipisah per field/baris/domain atau dibangun ulang sebagai turunan lokal. Label terakhir bukan perintah menyalin seluruh tabel.

| Domain                                                                                                  | Keputusan target dan writer                                                                                                                                                                                       |
| ------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Identity, tenant, membership, provider access, environment/site registry, product customer, entitlement | Move ke domain control. | Organization ID, klasifikasi, nama/status, profile operating unit, hierarchy purpose/version/node       | Move ke Organization Foundation tenant-scoped. ### Partisi party dan alamat

`OrganizationAddressBook::party()` bukan lookup murni. Ia dapat menyamakan nama/type, memanggil `PartyNumbers`, mengunci organisasi, membuat party, dan menulis `organization_parties`. Pemanggil baca/cetak melalui `locations()`, `contacts()`, dan identity dapat memicu pekerjaan itu. Setelah split, bootstrap canonical party harus melalui action Foundation. Pembacaan projection tidak boleh menerbitkan nomor atau menciptakan master.

Runtime pooled mempunyai empat organization-party link ke empat party dan satu lokasi terkait. Agregat snapshot tidak menemukan party organisasi yang sekaligus vendor atau lokasi yang juga ditautkan ke party lain. Ini bukan alasan menghapus penanganan overlap. Source mendukung lokasi bersama, sehingga rehearsal wajib mendeteksi overlap sebelum copy. Lokasi yang menjadi identitas bersama memakai satu authority dan projection untuk referensi ERP, bukan dua salinan writable.

`ref_provinces`, `ref_regencies`, `ref_districts`, `ref_villages`, `ref_postal_codes`, `ref_streets`, `ref_buildings`, `ref_group_of_houses`, dan `ref_land_plots` mempunyai `tenant_id`. Agregat saat ini menemukan nol nilai tenant terisi pada tabel tersebut. Nilai NULL tidak membuktikan semua baris adalah reference global resmi. Provenance/import dan konflik tetap divalidasi. Controller source menyebut method tulis tenant sudah tidak mempunyai route; jangan memasangnya kembali sebagai efek split.

Pemisahan organisasi dan party memakai konsep dari [Organizations and organizational hierarchies](https://learn.microsoft.com/en-us/dynamics365/fin-ops-core/fin-ops/organization-administration/organizations-organizational-hierarchies) dan [perencanaan Address Book](https://learn.microsoft.com/en-us/dynamics365/fin-ops-core/fin-ops/organization-administration/plan-configuration-global-address-book-additional-address-books). Penempatan Foundation tanpa pembelian ERP adalah keputusan produk Metta, bukan klaim perilaku atau parity Dynamics.

Manifest menandai 116 kandidat FK per database. Durable operation mempunyai operation ID, payload hash, authority/source revision, target environment, desired-state revision, lease, dan correlation/idempotency ID. Commit pusat menyimpan state dan pekerjaan bersama. Commit target menyimpan efek dan receipt bersama. Ack yang hilang mengulang receipt, bukan efek. Payload berbeda pada operation ID sama ditolak. Revision lama/gap dan tombstone ditangani eksplisit. `afterCommit` tanpa catatan durable tidak memenuhi kontrak ini.

## Identity dan kewenangan

Principal bersama mempertahankan `users.id` bigint. `ProductCustomer` UUID tetap sebagai identitas binding legacy yang dipetakan eksplisit ke principal melalui `issuer + subject` terverifikasi. Tidak mengganti semua ID menjadi UUID, tidak mencocokkan email, dan tidak mengubah subject SSO. Konflik memerlukan resolusi; akun yang belum terhubung tidak memperoleh akses otomatis.

Agregat runtime menemukan satu ProductCustomer aktif dengan exact subject link, nol subject dengan beberapa user binding aktif, dan tiga managed resource aktif tanpa customer binding. Tidak membaca identitas orangnya. Resource tanpa owner tetap pending claim; operator/requested_by atau email owner bukan bukti kepemilikan customer.

| Keputusan                                                 | Authority target                                                                                                                                                                           |
| --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Orang menjadi anggota organisasi                          | Membership pusat, status dan revision. Tidak ada `system_role`.                                                                                                                            |
| Anggota mengelola tenant, undangan, grant atau Foundation | Catalog/assignment pengelolaan pusat dengan chain role → duty → privilege → permission → entry point. Resource dipisah sesuai kontrak; nama role adalah data. Lindungi pengelola terakhir. |
| Operator menjalankan operasi provider                     | `provider_access` dan gate operator. Bukan Owner customer otomatis.                                                                                                                        |
| Tenant berhak memakai produk                              | Entitlement pusat dengan waktu berlaku. Hak ini tidak menciptakan membership, grant atau instalasi.                                                                                        |
| Anggota masuk environment                                 | Grant pusat + membership + desired state/expiry + entitlement relevan + receipt lokal yang sah. `environment_members` saat ini hanya indeks navigasi.                                      |
| Orang melakukan pekerjaan ERP                             | Role bisnis, duty, scope dan Owner ERP lokal. `OwnerRoleDuties` dipertahankan sesuai kontrak ERP.                                                                                          |

Chain pengelolaan pusat belum ada pada source/schema yang diaudit. CPDB-01 mengunci domain dan resource-nya; bukan memindahkan seluruh tabel security ERP atau menganggap Owner ERP berubah menjadi role platform. PF-01 menggunakan satu action tenant bersama, dengan pemisahan identity dan bootstrap ERP ini sebagai dependency desain.

## Policy, group, profile, custody dan pembayaran

`contracts.json` menetapkan field logical minimum, bukan nama tabel/API yang sudah terpasang. Tidak ditemukan schema policy/profile/ack target itu pada baseline. Foundation menyimpan metadata authority dan binding, sedangkan pasien, episode, obat/jasa, stok, uang dan transaksi tetap di aplikasi pemilik.

| Kontrak               | Keputusan yang dikunci                                                                                                                                                                                                                                |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Domain group          | Patient registry, clinical-record access, item catalog, service catalog, pricing/availability dan inventory source independen. Tenant, anggota Organization ID, authority produk/environment, mode/capability, revision dan effective date eksplisit. |
| Write binding         | Satu context/domain/effective interval mempunyai tepat satu authority aktif. Hierarchy, grant dan placement tidak menjadi alias satu sama lain.                                                                                                       |
| Publication/ack       | Published revision immutable. Effective per target menunggu compatible adapter/schema ack, hash dan checkpoint/receipt. Pembatasan akses tetap mencabut akses lama ketika ack terlambat.                                                              |
| Service group/profile | Assignment unit utama/pendukung berversi, serta binding pasien terpisah dari katalog/stok. Nama profile dibuat admin sebagai data, bukan enum customer atau cabang kode. Process instance dipin ke version.                                           |
| Catalog               | Satu authority per key/field; release obat/satuan atau definisi jasa lengkap sebelum aktif. Pricing, section, komponen biaya dan akun lokal hanya berubah lewat override yang diizinkan.                                                              |
| Legacy/shared data    | Mapping tenant/org/product/environment/local type/local ID, bukan nama/ID integer saja. Default isolated tidak memutus relasi shared lama; merge/split berisi data memerlukan preview, backup, fencing dan rekonsiliasi.                              |
| Custody               | Requesting/clinical org, procurement party, stock owner, custodian/lokasi, fulfillment unit/authority, eligibility/profile dan agreement reference disimpan terpisah. Satu owner dengan custodian berbeda bukan pool dua owner.                       |
| Pembayaran            | Seller/billing issuer, receivable/revenue beneficiary, collector dan settlement reference terpisah. Clinical realization, issue receipt dan billing/collection/settlement mempunyai state sendiri.                                                    |
| Reversal              | Origin environment/order, authority, owner, lokasi/lot, policy/process revision, invoice dan alokasi kas asal dipertahankan. Retur/refund tidak memakai routing terbaru untuk mengganti pihak.                                                        |

Mode pemerintah, swasta, yayasan dan pengelola lain menggunakan kontrak netral yang sama. Tidak menanam nomor unit, section, nama customer, atau pembelian ERP sebagai syarat Foundation. Studi legacy pada [custody](SUPPLY-CUSTODY-AND-PAYMENT.md) tetap mempunyai batas bukti lamanya; tidak dilakukan pembacaan ulang atau write ke legacy dalam CPDB-01.
